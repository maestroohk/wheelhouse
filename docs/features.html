Wheelhouse

One room to steer agents across every repo you own. You give short instructions; agents work in parallel, each in its own isolated copy; you get back a card you can read in ten seconds and a decision you can make with one click.

The problem it solves: with ten projects on the go you lose track of which repo was mid-change, which agent was waiting on you, and what each one actually did. Long markdown reports make that worse. Wheelhouse keeps the state of every project on one screen and never makes a wall of text the default.

Four rules the design follows

Cards, not documents

Every mission ends in a fixed-shape brief: one headline, up to four bullets, what was verified, what is risky. The full transcript exists but is never what you see first.

Only decisions interrupt you

An agent that needs a choice stops and asks with buttons. Everything else stays quiet until it is done.

Your working copy is never touched

Changes happen on a wheelhouse/* branch in a separate folder. Nothing is pushed. You keep or discard.

Every repo, one glance

Each project shows branch, unsaved work, running agents and what is waiting on you, so switching between ten projects costs nothing.

Features

Building

Fleet

Finds every git repo under your projects folder. Pin the ones you are active on. One line each: branch, uncommitted files, ahead/behind, agents running, decisions waiting.

Building

The helm

One instruction box, always on screen. Type @repo to target one project or several; the same instruction fans out to each as its own mission.

Building

Two mission shapes

Scout reads and reports, changing nothing. Ship makes the change on an isolated branch.

Building

Three autonomy levels

Scout can only read. Builder can edit files. Engineer can also run build, test and package commands inside the isolated folder.

Building

Live status line

What each agent is doing right now in a few words, with step count, time and cost. No scrolling logs.

Building

Briefs

The agent is required to report in a fixed structure. Wheelhouse renders it as a card and adds facts it measured itself: files changed, lines added and removed, check results.

Building

Needs-you inbox

Questions with option buttons, missions ready for review, and failures. Answering a question resumes the same agent with its memory intact.

Building

Review, keep, discard

Per-file diff in the app. Keep commits as you on the mission branch; Discard deletes the branch and folder. Send a follow-up to have the agent revise.

Building

Checks

After a Ship mission, Wheelhouse runs the repo's own build and test commands (found from .sln, .csproj, package.json) and puts pass or fail on the card.

Building

Taking in outside work

Work another agent did in its own worktree can be handed to Wheelhouse. It gets the same checks, card, diff review and keep or discard as a mission started here.

Building

Logbook

Per repo: the last things done there, by you and by agents. Answers "where was I?" when you return to a project after a week.

Building

Limits

Cap on agents running at once, a time limit per mission, cancel at any moment, cost per mission and per day.

Next

Playbooks

Saved instructions with blanks: "add tests for…", "upgrade packages", "review this branch". Shareable as files in the repo so a team gets the same ones.

Next

First mate

Give one goal that spans projects ("add health endpoints everywhere"). A planning agent splits it into a mission per repo; you approve the plan, then it runs.

Next

Fix-until-green

When checks fail, the agent gets the failure and tries again, up to a limit you set.

Next

Push and pull request

From a kept mission: push the branch and open a PR with the brief as its description. Always on your click.

Next

wh command line

A small CLI so agents and scripts can start missions and read briefs in compact output. This is how any agent, including this one, works through Wheelhouse.

Next

RepoPulse link

Turn a deep-scan finding or a to-do into a mission; mission time and outcomes flow back into your standup and timesheet.

Later

Night watch

Queue work to run while you are away, with a spending cap, one commit per step, and a morning summary.

Later

Other agents

The agent runner is a plug-in point. Claude Code first; Codex, Gemini CLI and local models can be added without touching the rest.

Later

Explain mode

A "walk me through it" button on any brief: the agent explains the change at the level you choose.

Later

Team rules

Per-repo policy file: which autonomy is allowed, which paths are off limits, which checks must pass before Keep is enabled.

Later

Tray and phone alerts

A Windows notification when something needs you, so the tab can stay closed.

Who it is for

Senior

Run ten streams at once and spend your time on review and decisions. Policies and checks keep agents inside the lines you set.

Mid-level

Hand off the routine work (tests, upgrades, small fixes) and keep the interesting change for yourself, without losing track of either.

Junior

Safe by default: nothing touches your working copy and nothing is pushed. Scout missions and Explain mode turn any repo into something you can ask questions of.

How it is built

A .NET 10 API on your machine owns repos, missions, worktrees and checks, and streams events to a Next.js UI. Agents are started through the Claude Code CLI you are already signed in to. Data lives in %USERPROFILE%\.wheelhouse. Nothing leaves the machine except what the agent itself sends to its model.
